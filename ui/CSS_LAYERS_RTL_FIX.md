# Material UI CSS Cascade Layers & RTL Compatibility

This document explains the issue encountered when enabling CSS Cascade Layers (`enableCssLayer` and `modularCssLayers`) in Material UI with Next.js App Router and Right-to-Left (RTL) layout support.

## Issue Overview

When enabling CSS cascade layers via `enableCssLayer: true` (in the Emotion cache provider options) and `modularCssLayers` (in the theme options), the application's RTL layout broke, and the dark theme failed to apply correctly.

The root causes were:

1. **RTL Plugin Layer Awareness**:
   The application configured the Emotion cache in [MuiEmotionCacheProvider.tsx](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/components/theme/MuiEmotionCacheProvider.tsx) using the legacy, community-maintained `stylis-plugin-rtl` package:
   ```typescript
   import rtlPlugin from "stylis-plugin-rtl";
   ```
   This package has compatibility issues with CSS Cascade Layers (`@layer`) because it does not correctly traverse or parse styles nested within `@layer` at-rules. As a result, properties were not flipped to RTL (e.g. `margin-left` remained `margin-left` instead of becoming `margin-right`) when styles were wrapped in `@layer mui`.

2. **Cascade Layer Order Mismatch and Name Corruption**:
   The theme option `modularCssLayers` in [CreateFromPalette.ts](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/components/theme/CreateFromPalette.ts) was defined as:
   ```typescript
   modularCssLayers: '@layer theme, base, mui, muirtl, components, utilities;',
   ```
   The Material UI styling engine dynamically replaces the key `mui` in the `modularCssLayers` string with its sub-layers (`mui.global`, `mui.components`, etc.) using a global regular expression.
   Because the string contained `muirtl`, the prefix `mui` inside `muirtl` was also matched and replaced, resulting in a corrupted, malformed layer statement in the document `<head>`:
   ```css
   @layer theme,base,mui.global,mui.components,...,mui.sxrtl,components,utilities;
   ```
   This corrupted syntax caused the browser to fail to properly order cascade layers.
   Additionally, since `AppRouterCacheProvider` hardcodes all wrapped styles to `@layer mui`, the custom key `muirtl` was completely ignored as a CSS layer, making its presence in the order declaration unnecessary.

3. **Theme Script Attribute Mismatch (Dark Mode Issue)**:
   In [layout.tsx](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/app/layout.tsx), the initialization script for CSS variables was set to:
   ```tsx
   <InitColorSchemeScript attribute="data" />
   ```
   However, the theme was configured with:
   ```typescript
   cssVariables: {
       colorSchemeSelector: "class",
   }
   ```
   and next-themes was configured to toggle class `class="dark"`.
   This mismatch meant that the initial theme script expected to use `data-mui-color-scheme="dark"`, while the CSS styles generated by the theme targeted the `.dark` class selector, causing dark mode to break on load and display light theme components.

---

## Resolution

The following actions were taken to resolve the issues:

1. **Swapped to First-Party RTL Plugin**:
   Updated [MuiEmotionCacheProvider.tsx](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/components/theme/MuiEmotionCacheProvider.tsx) to import the official, first-party `@mui/stylis-plugin-rtl` package, which has been specifically updated to support `@layer` nesting and correct parsing of CSS layers:
   ```typescript
   import rtlPlugin from "@mui/stylis-plugin-rtl";
   ```

2. **Cleaned Layer Order Declarations**:
   Removed the unused and prefix-colliding `muirtl` layer name from:
   - [CreateFromPalette.ts](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/components/theme/CreateFromPalette.ts):
     ```typescript
     modularCssLayers: '@layer theme, base, mui, components, utilities;',
     ```
   - [globals.css](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/style/globals.css):
     ```css
     @layer theme, base, mui, components, utilities;
     ```

3. **Aligned Dark Theme Attribute**:
   Changed the `InitColorSchemeScript` attribute to `"class"` in [layout.tsx](file:///c:/Users/mkupe/Code/system-b15/bluz/ui/src/app/layout.tsx) to align it with next-themes and the theme's color scheme selector:
   ```tsx
   <InitColorSchemeScript attribute="class" />
   ```
